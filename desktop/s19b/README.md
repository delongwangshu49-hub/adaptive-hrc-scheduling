## 准备与打开

先按[项目环境说明](../../docs/setup.md)准备根CPU环境。Windows命令在PowerShell7中执行，从仓库根目录运行：

```powershell
uv sync --project desktop/s19b --locked --python .venv/Scripts/python.exe --cache-dir .local/s19b-uv-cache --link-mode copy
./scripts/start_s19b.ps1
```

桌面环境独立位于 `desktop/s19b/.venv`，锁定PySide6-Essentials6.12.0与同版shiboken6；不向根CPU环境或Isaac安装Qt。基础CPU wheel仍无运行依赖。原型依赖当前仓库源码及根CPU解释器，尚不是可离开仓库运行的桌面安装包。

首次使用在“连接设置”选择现有Isaac安装目录，要求其中有 `python.bat`。设置和语言偏好只保存在 `.local`；中文开发默认界面可通过右上角切英语，语言选择不修改运行或草稿。

## 试用顺序

1. 选择CPU或Isaac入口，编辑SR-W1/SR-W2、1—3产品、逐产品释放时间与备注。每次运行采用单一产品类型；运行前配置仍须通过原场景/准入规则。
2. 点击“检查输入”，勾选“允许提交本次运行草稿”，点击“确认并启动生产”。确认框展示固定草稿与后端；返回时不提交。提交后等待后端独立校验及实际初始化确认，运行中草稿固定，重复启动不会创建第二个worker。
3. 查看运行编号、源码/配置摘要、仿真时间、数据年龄、当前动作与审计状态。Kit作为主界面的原生子窗口显示在中央区域，随主窗口缩放和收起；工作台请求相机显示操作；原模型尺寸、碰撞、路线、手位和生产参数保持。
4. 需要结束时点击右上“请求有序停止”并确认。后端在下次派工前边界禁止新派工，通过原CPU/真实USD读回处理已启动动作，保留未完成订单和未来承诺。受理、处理、保存审计、Kit完整关闭及实际退出分开；HOLD/无进展保留为停止受阻/失败，不声称停止成功。停止后不提供继续生产。
5. 断连/超时期间显示未知，控制暂时禁用；“核对并重连当前运行”只核对同一运行和未决请求，不重放命令。前端意外退出后重新打开工作台，选择“恢复已有运行连接”和原目录；已有进程由PID及内核创建时间核对，不能重启该运行的后端。已退出且实际退出回执齐备的运行只读打开；缺失/损坏记录保持未知。
6. 点击“查看本次证据”或“历史记录→打开运行记录目录”，查看报告、配置、两审计、控制受理/完成与真实截图。身份不全的旧记录如实标记，摘要不一致或损坏记录拒绝。需要新生产时先等待本次实际退出，再确认新草稿和新身份。

## B1信息与只读定位

右侧同时显示运行/请求身份、配置和源码摘要、数据年龄、真实连接/退出、产品及动作状态。短身份的完整值可看提示和证据；右栏滚动查看定位、相机与证据按钮。点击订单或动作单元格可选中对应稳定对象ID，再使用“只读定位”；也可在对象框输入已有人员、设备或动作ID。

定位只调用当前Kit的USD选择接口，订单定位到已存在实体，动作定位到已映射的物料/实体与设备；不把逻辑动作虚构为新USD节点。确认包含实际选择路径及前后场景/生产状态摘要。部分关联目标尚未映射时单独列出；未映射对象由显示端实际拒绝，CPU/历史及断连时不开放定位。当前静态操作目录不覆盖所有后端动态服务动作，未知ID仍不可定位。定位不会移动对象、编辑模型或向规划器发送信息。

下方“最近决策原因”来自后端在线日志的最终原因（尚无最终回执时显示提案原因），保留观察编号/时刻、日志序号、对象与原始原因码；它不是所有当前订单等待原因的重新推断。已审阅原因有中英解释，未提供原因明确未知，未翻译原因保留原码。订单状态与最近一次决策/动作开始回执不同，检查点也不代表订单完成。切换语言不改变输入、运行、请求或事实。

超过5秒未取得有效状态、消息身份/版本不符、文件缺失或损坏时，当前事实显示未知并禁用定位/相机。已提交、实际后端确认、拒绝、未知、检查点保存与Qt实际退出分别显示；退出后只显示保存的检查点事实。

证据入口在检查点显示仍打开时也可只读预览。新记录的`evidence-index.json`绑定运行/请求/epoch与保存文件SHA256；打开及预览前重新核对。JSON与压缩事件/决策在只读文本区预览，最多显示24000字符；图片可用系统查看器打开。动态显示确认、Qt退出回执与后端封存分开，以身份和读回契约核对；索引是本地字节完整性检查，不是签名或外部可信认证。旧记录无索引明确完整性未核验，不改写它们；损坏、缺失或身份不符的记录不显示成功。

输出保存于 `.local/s19b-runs/<新运行编号>`。`request.json`记录输入，`sources.json`绑定源码和视口/依赖配置，`live.json`是带运行/请求/epoch/序列的状态快照，`report.json`保留终止原因与限制，`process-exit.json`来自Qt实际进程退出信号。无状态心跳时显示未知，不能从窗口仍存在推断生产正常。

B2增加`worker-claim.json`永久唯一worker声明、`start-command.json`与不可变`control-inbox/`命令、`control-state.json`持久受理和最终状态。请求绑定运行目录、固定输入及完整草稿；同一命令重发只核对原结果，同ID不同内容/旧epoch/乱序/非法状态拒绝。前端丢失后日志直接写文件，不依赖前端管道存活。恢复前端使用保留的Windows进程句柄观察退出；没有实际退出回执时不推断exit0。此为本地单操作者协议，非多用户签名或权限服务。

## 单窗口布局

按PR174，主窗口横向展开：左侧订单与启动输入，中央真实Isaac三维视口，右侧运行来源/订单状态/相机与证据，下方系统反馈。中英切换保持草稿和运行身份。CPU入口的中央区域明确为空，不冒用旧截图；历史入口仍为只读记录。

Windows使用[Qt原生窗口容器](https://doc.qt.io/qt-6/qwidget.html#createWindowContainer)承载当前运行对应的Kit窗口，只识别匹配运行/请求身份及实际worker PID的自有显示窗口。Kit窗口移除顶层边框，成为主界面的原生子窗口；启动时识别到本运行的Kit窗口即挂接；生产状态仍等待后端初始化确认。Kit/GLFW最小化恢复的旧坐标由容器位置同步纠正。运行退出后释放外部窗口包装，不把活的Kit窗口重新移到桌面。

这是当前Windows单机原型，跨进程[DPI差异](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setparent)与焦点仍需负责人实际操作/多屏核验；不据当前屏幕结果承诺所有平台。Qt普通控件抓图不保证包含GPU原生子窗口，三维显示通过实际Kit渲染和原生包含关系分别留证，不能把合成图称为完整窗口截图。

## 已有Isaac RC的退出与显示范围

使用自有 `sim/isaac/s19b_viewport.kit` 加载现有安装中的视口/RTX/物理扩展，关闭扩展注册表下载，保留既有USD生产适配器及RayTracedLighting。Kit体验加载实际MainWindow/DockSpace，让Viewport停靠并隐藏无关编辑面板及菜单；工作台相机菜单保留双语控制。`kit-ui-frame.png`来自实际Kit交换链，区别于只含三维的视口截图与无法保证捕获GPU子窗口的Qt抓图。

专用显示相机在 `/S19B/ReviewCamera`，从原相机预设复制显示参数；原 `/World` 人物、设备和相机预设保持。相机成功确认绑定实际渲染矩阵，不能只凭请求路径宣布成功。

当前6.1 RC的可见RTX路径曾在完整Kit关闭返回及脚本返回后滞留。本原型先保存并关闭全部证据文件、等待完整Kit关闭返回，再显式结束独立helper，由Qt核验实际退出码。它跳过该RC的解释器/插件最终收尾，不声称普通解释器退出已修复，也不用于实现B2生产停机。失败保留退出码1；完整Kit关闭未返回时不能写成功回执。运行中的关窗不会强杀后端。

Windows状态文件替换与瞬时分享冲突读取采用最长1秒的有界重试，保留旧的完整记录，不发布半份JSON。OptiX缓存使用独立本地目录，不删除原缓存；路径覆盖依据[NVIDIA OptiX缓存接口](https://raytracing-docs.nvidia.com/optix9/api/group__optix__host__api__device__context.html)。

当前属于事件边界的运动学显示，不是按墙钟1:1连续推进的生产动画或新物理验证。真实Kit截图与独立审计、合成接收边界及工业G2限制分别记录；前端性能尚待规定负载对照。
