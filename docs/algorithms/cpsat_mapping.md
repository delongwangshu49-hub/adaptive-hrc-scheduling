# S16 静态整数域与 CP-SAT 映射

版本 `S16-STATIC-1.1`，2026-10-07，PR132限定修复。本版只形成受限静态质量参照；完整建筑生产、动态闭环与非线性人因按原版本执行，HR资格门保持禁用。输入必须是显式 `Instance`，purpose为 `SYNTHETIC_STATIC_REFERENCE`，layout_version固定为 `S16-ABSTRACT-GRAPH-1`；不接受完整配置、隐藏情景或ExecutionSnapshot的隐式转换。原1.0已发布源码、样例、证据及审阅包保留原版本，当前入口拒绝显式1.0输入，不静默迁移。

初始状态限定为无在制/执行承诺、设备与人员无既有占用、成品槽为空，所有任务和静态释放/接收许可均已公开。设备位置及允许绑定须在输入设计时声明，不在求解中移动固定机器。带载中断、既有库存或动态恢复状态不能套用本接口；要比较此类输入须先扩展双方同域映射并审阅。

本版明确固定的是独立抽象资源图，不是S13真实场地布局：`S16-ABSTRACT-GRAPH-1`定义具名容量资源、角色绑定、班窗、前序和OUT/FG驻留区间的抽象规则，完整实例SHA-256同时绑定列明的资源实例、容量、资格、任务图、工时、费用及接收参数。几何位置、USD/AABB、路径和连续运动仍双方省略；不得将该标识填写为真实S13布局版本或据此声称生产/场地映射完成。S17及后续物流承接另需获授权的实际映射与验证。

## 数学编码及目标

对每任务t定义整数开始s_t、结束e_t，每alternative a定义选中x_ta，Σa x_ta=1；选中时e_t=s_t+d_ta。前序e_pred≤s_t，release≤s_t，e_t≤horizon及可选latest_end。选择alternative时每个角色的区间必须完整落在其某一班窗；各独立设备、人员及地点的占用需求不超过其capacity。不可用绑定在输入验证时拒绝，声明需求大于容量则模型合法但不可行。

产品占OUT1的后续驻留区间是[e_READY,e_STORE)，FG预留/驻留是[s_STORE,e_RECEIVE)。与READY劳动区间在端点相接。接收仍是有设备需求和release的普通任务；没有预定时刻伪释放，也没有窗口结尾强清库存。

最小化：`tardiness_weight × Σp weight_p max(0,e_receive-p.due) + makespan_weight × max_t e_t + cost_weight × Σt selected_alternative.cost`。整数权重/成本为合成单位；makespan包含所有任务，交期按外接收完成计。目标上界检查低于2^50，拒绝可能失去整数精确性的输入。READY与received另外记录，不能选择更好口径改写拖期。

规则参照在同一Instance和同一检查器上列排：只从前序已安排的任务取候选，产品due从receive标记向其全部前序传播，共享前序取最早due，保留大于horizon的真实交期。EDD按due/任务ID选任务，在各整数开始时刻按替代ID取首个合法模式；FASTEST_MODE按相同due/任务ID选任务，在同一开始时刻按(duration,cost,id)优先短时合法替代；SPT按最短声明替代工时/任务ID取任务，替代按(duration,cost,id)。无产品交期的独立任务在EDD类排序中置于有交期任务之后，再按ID排序。EDD与FASTEST_MODE有明确不同选择定义，个别输入上输出相同不代表策略相同。

枚举整数开始时刻后先检查可行、再接受；未完成驻留延至horizon，后续store/receive安排才收短。规则可能保守等待或无解，`NO_PLAN_FOUND`不是不可行证明。S16适配器不是把完整S11直接拿来对照，也没有实施S17 LNS。双方输入摘要完全相同；费用始终计入评价，规则局部最快未必总目标最好。

## 时间映射与误差

`tick_h`严格为表示正有理数的字符串，十进制如"0.1"或比值如"1/10"均由同一`grid_fraction`以Fraction精确解析。浮点、整数、布尔、Decimal/Fraction对象等非字符串网格字段均拒绝，不能由一侧二进制float和另一侧十进制str解释。参数验证、quantize及小时逆映射共用此网格解析规则；时间参数value_h仍按其字符串表示读入，exact模式拒绝非网格时刻，不用nearest变更可行域。逆映射为整数tick乘正有理tick_h，`check_hours`再精确转回检查。默认开发例tick_h="1" h；缩放0.1 h反映射测试不冒充真实工时校准。

JSON入口必须显式携带schema_version、purpose及layout_version，只接受对象和数组形状，数组先验证再转换为不可变tuple；资格、前序等ID必须保持完整原子字符串，角色/需求/班窗必须为二元素数组。标量字符串不能当数组逐字符展开，字符串也不能冒充一行角色绑定。直接Instance构造器提供当前参照版本默认值，其序列字段要求不可变tuple；序列化后包含完整元数据。未知字段仍拒绝，不将缺记录或非法引用变为默认合法计划。

确需保守整数化时，时长/释放/最小等待/班窗开始等下界使用ceil(value/tick)，horizon/latest_end/班窗结束等上界使用floor。每次返回实际tick与有符号误差，绝对值小于一个tick；固定链N项工时的上推误差小于N ticks。交期只影响目标，其映射选择和拖期误差须另声明。整数网格本身限制可选开始时刻，故即使参数在网格上，也只宣称两种整数域模型等价，不宣称与自由连续时间全域等价。保守转换后的可行域和最优值可能改变；双方必须同用新实例摘要并先审阅，不能作为原浮点完整生产最优界。

## 求解状态与预算

OR-Tools锁定9.15.6755，单worker、seed=0，常规solver预算10s，record另记含编码/独立核验的总墙钟；solver时限不包含建模和检查，不能称端到端实时保证。OPTIMAL仅表示该整数静态域已证明最优；FEASIBLE记录当前值、solver界和 `(value-bound)/max(1,abs(value))`，不称最优。INFEASIBLE有证明、无计划；UNKNOWN可能预算耗尽或solver停止、无计划不等于无解。二者在无incumbent时value/bound/gap均null。`SOLUTION_LIMIT`与预算/solver停止分开；非法输入/编码诊断抛错，不伪造UNKNOWN。

完全枚举使用无目标satisfaction模型；返回complete仅在solver证明穷尽且未触发solution cap时为真。独立oracle从各任务所有(替代,整数时刻)作笛卡尔积并独立检查，不读取CP-SAT生成结果，候选超过预算则明确拒绝，不把抽样当完整集合。

规则默认预算10s覆盖其搜索及候选检查，并有100000次试排上限；CP-SAT记录的是solver内核预算和另列总墙钟。二者预算组成明确分开，本步核对可行域/目标及手算质量，不据这些墙钟或几条开发例宣称公平算力下的效果/速度优势；正式比较预算仍须后续协议裁定。

## 手算小例与反例

四个完整集合：CUT1两任务工时2/1及horizon4，最短3；加入A→B后最短3；两焊接设备/具名工人及班窗，慢模式占WELD_B两单位、B同占一单位，最短3（快模式另有费用3，规则值5）；READY1+store1、receive许可3/时长1、due3/产品weight2、搬运费用2，目标4+2+2=8。完整集合分别6、3、11、9条；枚举与模型逐条一致，目标由独立检查器算出。

B=2、三件：READY固定结束1/3/5，前两件store于1—2/3—4，第三件在OUT1从5等待；接收许可8，前两件同时8—9接收完成后才腾位，第三件store9—10、receive10—11。makespan下界11、三次搬运成本6，最优17。B=3开发对照可三件8—9接收，最优15。固定READY时窗用于见证背压，并非修改生产recipe。将第三件store提前到8—9，独立FG容量检查拒绝；延后第一件搬运到与下一READY冲突时，OUT1驻留检查拒绝。

专项覆盖替代选择/目标、各设备与人员容量、distinct角色/资格、班窗、前序、release、latest_end、horizon、时间整数化、版本/身份/完整性、B+1驻留及接收反例，并保存真实零预算与回调提前停止状态。失败及本轮工程检查见[S16步骤卡](../steps/S16.md)。例子仅是开发验证，不形成正式A/D效果结论。

实现API依据[OR-Tools Python CP-SAT文档](https://or-tools.github.io/docs/pdoc/ortools/sat/python/cp_model)及[官方源码/响应契约](https://github.com/google/or-tools/blob/v9.15/ortools/sat/cp_model.proto)；发行及Apache-2.0许可见[OR-Tools 9.15.6755](https://pypi.org/project/ortools/9.15.6755/)。本仓库不再分发其二进制或改变自有代码许可，精确依赖/摘要在uv.lock。普通CPU检查覆盖reference组，Isaac环境不安装求解包。

## PR132限定修复与历史区别

F1采用严格字符串网格及统一精确解析；F2先验证嵌套对象/数组形状并保护原子资格ID；F3按接收目标传播due、避免horizon夹小，并区分EDD的ID选择与FASTEST_MODE的短工时选择；C1显式绑定抽象资源图版本。新增15项反例/控制回归，原15项在未修复r1上检出14个失败子用例和2个错误，修复后专项合计37项通过。接收反例原EDD目标5，新EDD及手排/CP-SAT为4；单任务替代A_SLOW=2、Z_FAST=1时，EDD选择前者、FASTEST_MODE选择后者，两者均独立检查合法。这些是修复/定义见证，不是正式算法效果比较。

原四个极小集合和七例生产参数保持，1.1样例仅增加版本/追溯字段及新的策略记录，旧摘要和源码由原r1标签/封包留存。原失败及发布事实保持。新增元数据不扩大物理/动态、人因、HR或工业资格范围；成果验收和新快照发布另审。
