# S19 在线预算、合法回退与计划稳定性

2026-10-09；PR155—PR156；调度仿真研究域 S18-SIM-A1。本文随 S19-2 本地修复更新；原 r1 结论及封包见 `docs/validation/S19_online_r1.md/json`，不由本文追改。本文不构成 S20 协议冻结、工业实时性或 A/D 方法优势结论。工业 G2 仍为 OPEN / NOT_ESTABLISHED。

## 时钟、触发和承诺

`OnlinePolicy` 接受已交付观察、对应实际事件前缀和已有决策记录。它没有外生场景表或未来到货、质量、接收许可入口。身份同时绑定配置摘要、运行 ID、epoch、仿真时间、状态及事件前缀；同一身份不能倒退到更短前缀。

首次决策、周期到点、已交付 WORLD/EXCEPTION/REJECTED、暂停后恢复触发重排。普通完成与时钟事件触发当前派工检查；周期未到时可继续核验缓存头部。每个搜索调用均计入预声明调用上限，异常和被中断调用也不退还次数。搜索额度耗尽后由执行完成、外部事件和日历驱动规则回退；预算 WAIT 仍按周期重试，避免无界同刻空循环。

原短预算配置继续采用 **未来承诺窗口 0 h**。实现另支持预声明的 `0 ≤ future_commitment_h ≤ horizon_h`：完整核验候选中进入该窗口的动作成为未来承诺，锁定操作/试次、顺序、模式、班组、服务及分支；原提议时刻作为开始下界，不能提前执行。它们不凭计划创建实体预留，也不保证设备故障后仍准时开始。新计划必须保持承诺选择，实际派工仍通过当前准入；观察到动作开始/完成或对应产品取消后释放未来承诺。

已经接受的动作进入实际承诺窗口，从接受持续到真实完成、合法恢复/处置及对应资源释放。这个窗口不受墙钟超时、暂停或规划时域末端截断。执行中动作、ModeAttempt、已绑定班组、材料预留、所有权、带载运动、支承和实物驻留均作为实际前缀保存。已有 EXCEPTION 的合法恢复优先于尚未开始的未来承诺，恢复不得改变或释放其余承诺；恢复控制器本身不等于修复设备。

仿真时钟单位为小时，用于工序、日历、触发周期和预测时域。计算预算使用 `perf_counter()` 的单调墙钟秒；两者不互换。现行驱动仍是无墙钟配速的离散事件/运动学闭环，S19 不增加实时物理线程或声称仿真时钟按 1:1 墙钟连续前进。计算开销完整记录，不从总耗时中扣除或以暂停隐藏。

## 搜索、核验与回退

每轮计时从观察与 PlanningInput 构造之前开始，覆盖前缀取得、搜索、候选核验、缓存/规则回退、派工前版本检查、准入与派工回执。控制器内耗时和整个周期耗时分别记录；最终回执超过预算也计为周期超限。

搜索保留 S18 完整名义窗口的模式、班组、优先序、开始时段和休息邻域。单次搜索额度不大于 50 ms 时，先生成显式 `initial_action_only` 保守初解：第一轮选择一个合法动作，随后对未承诺新工作执行 HOLD，并将全部已运行/已承诺动作、完成事件、日历与人员状态完整推演到原预测窗口末端。产品集合、约束和窗口没有缩减；不能达到末端或违反约束的初解仍被拒绝。这种初解不证明优于 EDD，也不能单独证明多动作未来计划稳定性。

剩余额度允许时，修复解除保守初解限制，尝试完整联合滚动计划。开始新修复前，以刚测得的生成加完整核验耗时预留额度，不够时保留已核验初解；这只是避免明显不够用的调用，不是最长执行时间证明。构造前缀、滚动生成、每个修复试次、逐步候选回放及独立执行/因果审计之间均有协作式中止点。只有完整核验通过、目标有效且未越过搜索截止点的候选才进入最佳可行缓存。修复错误或中断保留此前已核验候选；半份后缀、部分核验或迟到改进不进入缓存。已开始的试次、迭代、核验和耗时照实记账。

S19-2 明确调整内部计时分段：先在完整决策周期内校验已经交付的执行/因果前缀，记 `feedback_verification_seconds`；随后开启原 50 ms 未来搜索时钟。搜索内仍检查前缀身份，并计入未来候选生成、逐步物理回放和完整执行/因果核验。这与 r1 把全部历史前缀构造计入搜索的分段不同；原失败记录保留，不能将新分段结果冒充原实现通过。所有分段仍包含在从观察前开始的原 5 s 周期和反馈延迟测量内，没有把工作放到未计时后台。

`verification_seconds` 只计候选 `verify()`；另列构造、初解、候选门和修复耗时及候选通过门的时刻。耗时有包含关系，不重复求和。原子校验调用仍可能跨过截止点；即使总搜索随后因修复超时，也只能使用在截止前完整通过门的既有候选。

增量审计保存的是独立审计器重建的私有账本。仅当配置/运行/epoch/摘要和不可变事件前缀完全对应时，才复用既有前缀；任何变更必须重新审计。最终快照与决策记录也须匹配，已核验区间仅按同一不可变对象复用。候选分支恢复账本副本，默认离线审计仍从起点完整重建。候选生成和复验可以复用精确输入下的确定性规划参考结果，但每个候选仍重新物理回放及独立审计。缓存不会把执行器状态当作独立审计账本。

该实现不抢占正在执行的单个 Python 函数或独立审计。因此短预算可能超限；超限是测量结果，不能解释为硬实时保证。长预算诊断不替换短预算失败，也不将单元测试中的宽限用作性能达标证据。

选择流程为：

1. 尝试预声明预算内的新完整候选，保留其中已核验最佳解。
2. 当前没有新解时，可以继续使用既有候选的下一动作。已完成/正在运行的普通动作从暂定后缀移除；旧后缀的历史分数不当作当前状态的新分数。
3. 已交付扰动改变可行域时清除未承诺旧后缀，保留未来承诺及实际持有事实。缓存头部必须重新通过当前状态准入；承诺头部受阻则 WAIT，不能换成不相容的普通规则动作。命令身份/派发时间可在生成当前提案时更新，原提议时刻另存；最后派工门遇到观察变化则直接拒绝，不在门内偷偷改版。
4. 无合法缓存且尚有决策时间时，调用同域 EDD 规则生成器；保留人员走行、空返、装卸、准备、休息、材料/通道/成品容量等规则。规则输出仍经过当前准入。
5. 预算耗尽、暂停、中断、过期观察或无法确认合法时返回带原因的 WAIT。已发生事实不因 WAIT 被释放。

派工前再次绑定观察完整摘要、单命令计数、运行/epoch/配置、修订号、派发时钟、已观察拒绝及实际合法性。执行器仍执行自己的契约和物理预检；真实 USD 障碍可以拒绝一个名义合法动作，下一轮只能使用随后交付的反馈。控制器是单一派工所有者；不声明跨线程共享执行器的无锁原子事务。

实际派工 ID 统一按当前观察修订号、决策序号和动作 ID 生成，与候选缓存或规则回退来源无关。墙钟搜索出口不同但实际命令相同，不应仅因求解路径生成不同实体身份；命令模式、班组、服务、恢复绑定等字段仍完整比较。候选原身份、来源和摘要保留在独立在线日志中，不通过放宽比较器或改写历史事件消除差异。

暂停/恢复是控制器接口。暂停禁止新派工、设置求解中止标志并保留缓存和所有实际持有事实；恢复清除标志并重新触发当前核验。本步见证的是这个接口，不冒充 GUI 控件、人工作业验收或外部执行器停止能力；S19B 仍另行授权。

## 可复算的计划变化

每次决策记录计划变更前后仍未开始动作的 `(operation, attempt)`、顺序、模式、角色绑定及计划开始小时。已完成/运行中的动作先从比较域排除，它们的执行保护通过实际状态锚点与独立 S10 审计检查。

对前后共有键计算：相对顺序的逆序对数、模式变化数、角色绑定变化数、开始时刻变化数和开始时移绝对值之和；另列新增、移除和可比较动作数。插入一个新动作不会把其余所有动作误算为重排。新增/删除不会伪装成模式不变。规则回退通常只有一个即时动作，其未来稳定性信息少；没有可比较项时保留分母为 0，不把它解读为长期计划稳定。

开始时移比较的是保留的缓存或规则暂定列表中的提议时刻。缓存头部在派工前绑定当前仿真时刻，原缓存列表仍保留候选的名义时刻；实际派工相对名义计划的偏差须从实际决策和事件另读，不计作此处的暂定计划变更。该指标不单独证明实际开始时刻稳定。

S19-2 另记录逐轮承诺加入/释放、所选提案、STARTED 回执，以及 `actual_h − proposed_h`。`audit_online_continuation.py` 从保存候选摘要、候选命令、实际事件和逐轮记录独立核对承诺的来源/顺序/模式/班组、取消所属产品及实际开始偏差，分别汇总未来承诺数、保护比较数、实际开始数、延迟开始数和总/最大延迟。保持名义时刻不变而实际晚开始，会明确计入延迟，不作为零变化成功证据。`replay_online_candidates.py` 另从保存实际前缀完整回放每个候选，不使用增量审计捷径；离线耗时不能计入在线预算成绩。

`online-journal.json` 保存前后列表、指标、观察摘要、事件数、保护状态摘要、搜索出口与实际时间。`audit_online.py` 用独立实现重算变化量，从保存的实际事件重建观察及保护字段，并复算超限标志和反馈墙钟差。它还逐项绑定实际决策记录，单列有证据的接口暂停和驱动末尾检查点，核对测量前缀之后至最后观察之间的反馈事件集合，并重算周期和反馈时延分布；遗漏日志行不能仅凭剩余行合法而通过。它不调用规划器，也不把自产 PASS 当作生产合法性；生产执行审计、决策因果审计仍分别执行。

零事件前缀从保存配置重建初始状态。配置先通过严格结构解码，再恢复其原 JSON 数值表示，避免把整数坐标 `12` 转成 `12.0` 后错误拒绝原字节绑定的保护摘要。事件已发生后的保护字段直接取自保存事件；这项处理不修改原日志、数值或摘要，也不放宽保护字段的比较。

## S19 发布后审计修订

F1 修订将指标复算与来源核验连在一起：上一轮未开始列表按实际运行/完成状态过滤后，必须等于本轮 `before`；新候选绑定本轮观察摘要，缓存只接受已在该运行/epoch 出现的候选。`after` 的顺序、字段和名义时刻须来自候选、连续保留的计划、可追溯承诺或本轮实际规则命令；所选提案再绑定该列表。实际 STARTED 回执 ID 和完整命令还须与驱动决策一致。仅把日志中的名义时刻改成实际时刻，或同步重算一个删空比较域的指标，都不能通过。

核验使用独立的 `audit_online_provenance.py`，不调用在线规划器。候选合法性、实际执行合法性与因果性仍由各自重放/审计检查；文件摘要另保护整份证据的完整性。这些检查不认证墙钟探针本身，也不把一致的日志等同于工业现场事实。大日志按事件顺序读取状态，不同时保留每次观察的完整状态副本。

F2 修订在执行和因果检查点复用、行前缀恢复、私有行捕获中比较精确类型，拒绝用 Python 数值相等的 `0.0` 或 `False` 替代整数索引来复用 PASS。可变行仍保留私有副本，合法不可变记录继续使用缓存。F3 修订为精确 JSON 与原生解码的原子缓存区分正负零；显式 `normalize_numbers=True` 的归一化语义保持。

本轮修复结果及实际验证范围见 [S19 有限修复审阅](../validation/S19_limited_repair_r2.md)；原始历史报告、失败和已发布快照不重写。

## 计时边界和证据

`OnlineTiming` 使用嵌套计时扣除子调用，独立汇总调度、执行状态处理、事件写入、观察交付、适配器事件处理、USD 运动学/读回和 Kit 应用更新。探针对执行器事务副本保留正确的方法绑定；有/无探针必须产生相同实际事件和决策。

反馈延迟从事件实际生成墙钟到首次规划器观察，再到该次决策周期结束；保存三个时间戳，不能用仿真时间差替代。末尾尚未观察的事件单列。端到端周期包括派工前全部核验及回执处理，Kit 更新另计且包含在整段墙钟内。导出压缩日志、离线独立复审和启动 Kit 的开销不当作单轮调度时间。

Headless Kit 的应用更新不是显示帧率，USD 运动学读回不是动力学性能认证；轻量后端没有物理/渲染指标。独占分类和周期总时间有包含关系，不直接相加。报告给出样本数、总量、最大值、P50/P95 以及超限次数；平台匿名摘要只覆盖实际受测配置。

`elapsed_s` 从探针安装计到报告生成，包含驱动末尾的执行/因果离线审计；进程总墙钟还包括 Kit 启动、日志导出和退出。因此两者都不是纯调度或纯场景更新耗时。周期分布单独来自观察构造至派工回执的实际计时，候选在线核验包含在其中；分类计时未覆盖的总墙钟不擅自归因给物理或渲染。单次运行内的多个周期也不是多个独立重复实验。
