# 负责人图审发现：生产场景悬浮支承

本问题来自S19B B1实际试用图审，属于既有生产场景建模，不属于双语词条或UI配色。当前 **OPEN / NOT_FIXED / GEOMETRY_AND_PRODUCTION_CONTRACT_PRESERVED**；不将B1程序通过或旧静态外观验收当作此问题关闭。

## 这些东西是什么

图中的大量白色短杆可追溯到两类既有USD对象：

| 对象 | 实际建立入口 | 用途与缺陷 |
| --- | --- | --- |
| 每个具体材料落点的固定短支承 | `sim/isaac/scene/production_port.py`中`support_aliases`循环，按材料落点高度建立两个0.06×0.5×0.04m横杆 | 用来提供既有落点接触/碰撞见证，但高处短杆缺少连续可见支架连接；不是应该漂浮的材料 |
| 可移动横杆与停放托片 | `sim/isaac/scene/production_support_port.py`及`production_supports.parking` | 六处共132根横杆与132块托片，按0.05m层距停放；高处托片/横杆缺少实际几何承载连接，形成密集悬浮阵列 |

这是可视建模缺陷，不能解释成正常生产效果。既有执行是运动学见证，位置和可见/碰撞读回一致并不证明杆件能承载或不会在重力下落下。

## 实际只读证据

首轮反馈验证的真实Kit检查点中，`scene-support-diagnostic.json`扫描711个可见且启用碰撞的USD对象，识别510个上述支承对象：246个固定触点横杆、132块停放托片、132根可移动支承横杆。以可见碰撞体世界轴对齐包围盒相邻关系、2mm接近容差与低处节点为起点筛查，238/120/120个分别未连到地面起点，共478个。

这个AABB连通性筛查是几何诊断，**不是结构计算、接触力仿真或工业安全证明**；可能把包围盒重叠误认为接触。它与截图及建立代码共同说明当前视觉缺少承载结构，而不是据此推断实际工厂可用性。

诊断前后整个USD根层文本摘要相同，未移动、隐藏、删除、修改尺寸或碰撞。B1修订仅增加只读证据入口；模型、生产规则、工时、容量、人因及观察隔离保持。原图、原封包与失败保留。

## 独立修复所需范围

不能通过隐藏短杆、关闭碰撞、删除未来落点或改掉模型坐标把画面变干净；这些动作会掩盖问题或改变现行契约。应单独核查：

1. 将固定触点横杆逐一关联到承载框架，保持原触点位置和尺寸，明确连接件/立架的坐标、几何及碰撞变化。
2. 为停放的移动支承定义完整存放架，检查现有杆件取放、换装路径、人员站位及叉车/推车通道；不能只增加装饰架后声称物理问题已修复。
3. 对新增或变更碰撞形成具体冻结项修订表；核验所有现行支承动作、遮挡/接触/动态扫掠、原数字及完整双后端生产回归，再另作可视审阅。
