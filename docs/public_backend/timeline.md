# P044 timeline stream

Format: `P044-TIMELINE-2`. Every packet carries sequence, previous packet digest, canonical SHA256, and a source envelope. The envelope binds run, epoch, RunSpec, frozen configuration, applicable catalog chain/materialized hash, state revision, observation, complete delivered event prefix, plan version and sampled/received simulation time. Only already delivered facts are projected.

Rows have stable IDs. FACT_PREFIX spans start at actual STARTED and close only with COMPLETED/readback. Open rows stop at observed_until_h and do not acquire a fabricated completion time. RESOURCE_FACT follows actual ownership acquisition/release, retaining holds past command completion. Equipment association resolves the admitted command's original static or service operation; equipment demand alone is not occupancy. PERSON_INTERVAL contains original F/E/activity values plus presence, availability and labour cost. MARKER separates world changes and exceptions. Order product status distinguishes ready, received and cancellation through business results and visible catalog.

PLAN has independent schedule_state (COMMITTED, TENTATIVE, UNSCHEDULED) and proposal_state (CANDIDATE, ADOPTED, SUPERSEDED, or absent when unscheduled). Only a STARTED reference permits ADOPTED. An actual historical prefix is independent of candidate plans. Unknown ends are omitted with end_status UNKNOWN. Each plan record retains its observation/prefix, reason events, original plan and policy journal (old/new choices, budget, cache/candidate origin); only actually exposed choices are shown. The packet also contains visible orders, people, devices, failed resources, personnel statistics, scene bindings, business results, receipt increments and cache transitions. No future request payload is used as a business row.

Consumer: `adaptive_hrc_scheduling.timeline.TimelineConsumer`. Reconnect by replaying a complete verified packet prefix; `timeline-latest.json` alone is not a substitute. Duplicate current packet is idempotent; gaps, changed digests, wrong identities or false fact/adoption rows fail closed. `view` supports product/resource filtering and stale local age. `export` freezes JSON rows, envelope and selection. `compare_envelopes` returns SAME_OBSERVATION only when all relevant version/observation/prefix/plan/time fields match. P05 may use this API for the two views; no layout is implemented in this step.

Independent checker: `scripts/verify_lifecycle_session.py` rebuilds the final state, physical residuals, meter, raw event intervals, resource occupancy and personnel costs without calling the publisher or consumer. It checks every intermediate packet as well as the final replay. Packet and source snapshots are bounded test artifacts; long-run compaction/virtualization and UI latency remain future capacity validation.

Revision 2 carries frozen RunSpec/configuration once in `source_basis`; each packet carries original observation, visible generation/delta history, command bindings, raw person intervals and exposed plan versions in `source`. The consumer checks C0 with the production configuration codec, rebuilds the applicable catalog and business attributes, audits the delivered execution prefix, reconstructs all actual/resource/person/marker rows and validates plan rows. This also keeps unscheduled rows stable across repeated observations. Orders contain the effective NORMAL/URGENT priority, including initial priorities; future unapplied orders are absent.

Re-signed semantic corruptions fail closed and retain the last trusted view. Transport must originate from the selected run: digest integrity is not sender authentication. Legacy v1 streams lack the new proof and are not silently accepted by the v2 live consumer; use independent saved-run review. The offline verifier additionally binds packets to saved observations, decisions, command admissions and original workforce statistics, without importing the online semantic validator.

The lifecycle sidecar is `P044-LIFECYCLE-2`, retaining the compatible `P04.4-SESSION-r1` RunSpec. Zero-event callback stop binds initial revision/time. STOP retries consume a finite ingress batch without new business dispatch. A successful final commit requires both projection files, enumerated terminal/reason/limit consistency, and independently reconstructed commitment obligations; early FAILED saves may lack projections and do not qualify as successful final commits.
