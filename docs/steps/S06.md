## 交付与检查

[接口说明](../contracts.md) 定义不可变订单/工序/模式/阶段/资源/状态，严格 JSON 边界、单位、稳定 ID、配置和消息契约。显式 Q 结合人员技能、机器人可达、设备/夹具绑定；工序/阶段 DAG、物料引用及有限分类容量可校验。F3 显式逐件入料、目标预约及等待最后 reset。

机器人准备与显式 restore 描述承接 R3-01，在线规划投影及 K_t/实际 C/预测 Ĉ 与离线 J_eval 分离承接 R3-02。状态包含剩余基础净量、尝试号、速度样本与倍率；没有执行积分或事件推进。S05 两份规格示例原字节保留，另生成 T0 和扩展配置与消息样本，说明 ID 映射和继承参数。

最终统一 CPU 入口通过：Ruff、锁/环境检查、41 项 unittest（34 项 S06、原七项回归）、sdist→wheel 构建、独立 wheel 环境再次通过同组 41 项检查。测试包含多个负向参数子用例，不把两次运行相加当作 82 项独立测试。生成文件逐字节一致。检查范围与初期失败见 [检查摘要](../validation/contracts.md)；完整本地输出与封后摘要由审阅包交付。

这是接口层证据。资格/结构自洽不等于排程可行、无死锁或性能提升；输入投影检查不等于已验证调度器非预见性。S07 疲劳积分、S08 事件语义、S09 轻量仿真、求解器和实验均未开展；没有复跑 Isaac。共同 cap、速度与工时仍为合成参数，不能外推人体安全或物理可行性。后续执行器仍须实现时序、保护、清场资源选择及原子锁转换。
