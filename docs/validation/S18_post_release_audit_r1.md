## F1 / P2：班组修复与保留模式不相容，异常使有效初解丢失

位置：`src/adaptive_hrc_scheduling/algorithms/simulation_joint.py:295`—306；关联 `planning/production.py:117`、`control/simulation_joint_policy.py:227`—231 及 `:86`—87。

`repair()`先通过`genes(rng)`同时随机生成模式和班组，再仅复制被破坏字段。若破坏 CREW、保留 MODE，新班组可能来自另一个模式：保留 HR-seq，却复制 H 的 W1/W2。代码只处理“MODE 改变时同步班组”，没有处理反向兼容。`rollout()`由此进入规划器资格池的空集合 `min()`，抛出 `ValueError: min() iterable argument is empty`；单个修复失败没有局部返回，整个 search 异常终止。

**实际复现**使用已保存 ADAPTIVE_JOINT 第一个候选及其真实生产前缀，时刻 24.439733333333333h，窗口终点 32.439733333333336h。原候选独立复验有效，分数 `(-6, 41.79221312489005, 5.8914860168062555)`。直接 CREW 修复 seed=1 在 PRODUCT-1.W-B 复现异常；进一步调用正常 `search`，seed=2、1迭代、destroy_size=2、1修复试次、180s，自然抽取 `(CREW, START_SLOT)`，同样异常，没有修改执行准入或核验器。

真实策略调用仅替换预算分配的 seed，以固定复现该组合；实际搜索/前缀/复验代码保持。结果为 `WAIT / S18_NOMINAL_WAIT`、`schedule=None`，有效初解没有返回。账本记录 0迭代/1试次，实际已完成初解并进入一次修复，遗漏失败修复计数；墙钟正常记账。不是宣称原四条已发布配对运行曾发生异常，也没有证据表明不合格人员被实际派工。

影响 SR06/V03 的联合搜索可用性及异常路径预算可核查性。建议按**保留模式**生成班组，局部拒绝不相容修复并保留已核验 incumbent，异常工作量仍完整记账。修复后应覆盖 CREW-only、CREW+START_SLOT、MODE联动、已承诺班组及多次调用预算；不能只在上层吞异常并返回等待。本轮未实施修复。
