## F3 / P3 精确 JSON 摘要受正负零缓存顺序影响

位置：`src/adaptive_hrc_scheduling/contracts/codec.py:49`—51，调用方为 `contracts/production.py` 的摘要生成。

`_json_atom`使用 typed=True 的数值 LRU 缓存，但同为 float 的0.0与-0.0仍具有相同键。先编码0.0，再编码合法输入 `{"position_z": -0.0}`，得到的文本变成正零，摘要为 `4a300485600845eaa1278d26bb971cd7f794ed92ebf32d49bc5ed20f89d1c6a4`；先编码-0.0则得到原生 json.dumps 的正确摘要 `e2dae620ceb69ab9d412e1dc4c2eca4b6f0fa548320491aee8a78f39a0fd1e92`。

这破坏“精确 JSON 字节等价”的声明，使同一输入的摘要依赖先前调用。它不改变正负零的几何数值，也未在保留的生产结果中发现该差异，因此列P3。建议缓存键区分符号位或对该情况不缓存，并做两种调用顺序的字节等价检查。本轮未修复。
