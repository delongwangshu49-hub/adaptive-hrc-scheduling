## 调用与证据边界

```python
from adaptive_hrc_scheduling.checker import check_run

report = check_run(configuration, snapshot, window_h=240,
                   order_weights={"ORDER-1": 1.0})
data = report.to_dict()
```

输入为不可变建筑记录；snapshot中的events、intervals为待核原始记录，products/people/quality/locks等派生表只作交叉核对。检查器自初始未装配/未制造状态重建位置、材料、工作单元、前序、班组/设备、驻留、搬运、质量、返修、取消及接收。配置摘要自行规范化并计算，结构及版本自行核查。只共享不可变记录、单位和冻结边表；不导入执行器、契约语义校验、building_human或旧human_state，不调用准入函数，也不采用执行摘要的PASS。

`window_h`省略时等于日志快照终点T；指定时必须等于该终点，不隐式补齐或截取尾部。输入从0开始；从中途恢复点开始且缺前史不能作为完整日志。合法未完成前缀可以PASS，但指标仍保留未完成订单；因记录缺失无法判定则INCOMPLETE。错误和缺失同时出现时总状态INCOMPLETE优先，已证实FAIL发现仍完整保留，调用方须同时看findings，不能把INCOMPLETE解释为无违规。

| 状态 | 含义 |
| --- | --- |
| PASS | 已提供窗口内、声明适用范围的记录与独立规则一致；不表示全订单完成或工业可行 |
| FAIL | 证据足够且存在确切规则冲突；每项给出规则、对象、时刻及可用事件ID |
| INCOMPLETE | 缺记录、缺人/窗口、未知记录类别、不可解析版本/结构或计划缺少轨迹；绝不作为可行放行 |

报告包含`report_version/status/findings/metrics/reconstructed/rule_scope`。finding字段为`rule/object_id/time_h/code/severity/event_id`。重建输出含位置、驻留、材料、最新attempt及完整attempt_history、产品状态、服务承诺、锁、完整质量结果史、故障、试验水及READY/取消/接收时刻。指标的`validity`在非PASS时为DIAGNOSTIC_ONLY；这些部分累计数不能进入收益统计。机器摘要和两条单缺陷片段见[summary.json](../../examples/building_checker/summary.json)。完整输入与报告只保存在本地证据目录。

传入`plan`时必须同时传`observation`；核对版本、身份、sampled≤received≤observed、已见产品/事件、完成事实和评价集合。非空计划没有完整候选/实际事件轨迹时明确INCOMPLETE，不把预测完工当实际完成。S11可调用此接口核验其候选轨迹；本步不生成轨迹或排程。无计划输入时R14标NO_PLAN_SUPPLIED，有输入时只标SUPPLIED_VISIBILITY_ONLY；两者均显式注明S12_POLICY_NONANTICIPATION_NOT_TESTED。相同可见历史下动态策略动作是否一致仍是S12出口，S10不以空计划通过替代该证明。

## 指标口径与手算

全部仿真时间为h，疲劳F无量纲，暴露F·h；资源容量积分为产品·h或子框·h，不是几何面积。区间半开[s,e)，时刻事件零时长。按记录顺序重放，不自动排序/去重或修补缺失。

| 指标 | 集合、单位与缺失/未完成处理 |
| --- | --- |
| 产品与订单交付 | 产品行与计数涵盖窗口内已释放全部产品；逐产品READY/RECEIVED时刻和完成/未完成/取消并列。任一成员释放后订单进入评价，保留配置中该order_id的全部必需成员（含未释放者）；全部READY后才取最大值作为订单完成。C04无独立Order记录，完整组内最大due_h作为显式订单交期口径 |
| 加权拖期 | `order_weights`可给全部已释放订单的正有限权重；缺成员INCOMPLETE，未提供则公开声明单位权重。Σw·max(0,C−d)在有未完成非取消订单时为null；另报Σw·max(0,T−d)与已完成项组成的下界，不填0美化 |
| 取消 | 逐产品保留取消及已耗成本；订单中任何必需产品取消，则该订单单列取消，不进入非取消交付目标。C04没有部分订单修订契约，此口径不是自动删除其他产品；成员清单完整保留 |
| WIP | 已开始形成实物、未READY的产品等价数积分；未制造逻辑订单不重复算实体，多个子框归同产品计1；取消在制品保留，显式清场到Q1后退出生产WIP，Q1占位继续计算 |
| 占位 | 按各bay实际驻留与有效预留并集积分；J2同产品双框计1、BUF每子框计1，MOVE源/目标保守双占位；OUT1直到显式RECEIVED释放 |
| 等待/空闲驻留 | `process_wait_activity_h`计等待开始到释放完成含许可等待；取消在事件时刻终止尚未提交劳动的工艺等待，保留取消前累计和取消后物理驻留成本；`idle_residency_product_h`为物理驻留且无主动工作/服务/工艺等待的产品时长。它包含派工空闲，不能冒称全部为下游阻塞的因果损失 |
| 劳动/人员等待 | 全人员WORK/HANDOVER/RESTORE/SUPERVISE小时累加；WAIT另列，REST/OFF_SHIFT分别保留。取消、返修和尾部不删；所有人必须覆盖[0,T] |
| 搬运 | 已完成实际稳定转移次数，JOIN-IN三次子搬运各计1；设备占用时间按实际完整MOVE/清场一次累计，不乘人员数；未结束移动前缀另列`move_open_prefix_h`，不伪算已完成 |
| 返修 | 返修启动次数、完整诊断+修复服务小时与未结束前缀分别报；替换料消费由重建材料账保留，原料不退库；复验劳动/等待仍计入各自总量 |
| 人因 | 从配置F0和独立识别的活动率逐段重算F、E、peak；每人和ΣE/max E同窗口。恢复到0后面积为0，不清零历史E；不按执行器summary作为oracle |
| 计算成本 | `computation_samples`逐条wall_ms、budget_ms、fallback；报次数/总墙钟/超预算数/回退率，未提供为null，不能填0。检查器自身wall_ms单列，不充当调度器耗时 |

增长段：F₁=F₀+aΔt，E增量=(F₀+F₁)Δt/2；恢复段令u=min(Δt,F₀/r)，F₁=max(0,F₀−rΔt)，E增量=(F₀+max(0,F₀−ru))u/2。独立积分不调用旧数值核。浮点派生量对照使用1e-10绝对/相对容差，记录的cap、容量、落位/完工时界仍按硬界核查，不提前完工、不裁剪F。

实际手算对照：H-D1中d=0.5(1+0.5×0.2)=0.55h，劳动后F=0.2825；恢复到2h终F=0，总E=0.332203125 F·h。全15人纯等待2h时每人F=0.24、E=0.44，ΣE=6.6、max E=0.44、劳动等待=30人·h、WIP=0。完整SR-W1出厂位预留1h加READY后待接收1h，OUT1占位=2产品·h；实际搬运9次、设备4h。未完成订单T=240、d=168，最终拖期null、下界72h；权重3时下界216。均有测试断言。
