2. **内存门槛另有一对超限，FORMAL_PERFORMANCE_OPEN。** 第一对零预算约490.043MiB超过256MiB。
3. **Kit关闭根因未解决。** 原冻结零预算第三条A完成生产/双审计后，app.close未返回；等待约260秒后仅清理匹配PID/创建时间的本次worker。原报告closed=false及非零退出保留，未计入通过配对。后续重测通过不抹除该失败。成功运行仍沿用完整app.close返回后显式退出的RC兼容策略。
4. **覆盖限制保留。** B+1存在上述未知/过期样本；完整B2交互性能、其他规定负载的最终源码全矩阵、实际Kit宿主进程崩溃重建、物理IME/多屏未在本轮扩大覆盖。实际Kit序号验证采用同宿主显示字段重建；CPU另有真实前端进程丢失恢复。
5. 首次控制验证脚本因旧1MB状态读取上限报错，实际后端已正常停止/退出。验证脚本按已存在的历史状态读取上限改为20MB，后续通过；首轮失败保留。历史失败封包保持原字节，未追认或改写。

6. 最终检查首轮的uv全局缓存权限失败属于环境启动失败，改用工作区缓存后解决，原日志与非零回执保留。
