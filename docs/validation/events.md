| 验收问题 | 证据 |
| --- | --- |
| 同刻可复现 | 五类事件的全部 120 种排列排序一致；外生批次逆序结果一致；完成优先、零剩余未完成拒绝 |

## 开发中修正与限制

首轮 Ruff 指出新代码中的含混单字母变量和导入排序，已改正并保留诊断。新增测试初次通过后，AI 辅助代码复核发现依赖集合过宽：来源站在 rig 后仍影响 move，feed 在 setup 后仍影响 work。修正为当前阶段依赖，并加入反例；这是本地初版修正，不改写旧发布事实。另明确浮点净加工完成边界，避免有理数重算将声明的浮点整段时长误当越界；疲劳 cap 检查没有放宽。

状态由手工构造，局部转换要求调用方提供已推进到当前时刻且物理事实真实的快照。测试不证明完整资源获取、历史合法性、全部物料清场、任意输入正确性或真实调度器非预知性。当前确定性消费者仅为接口见证；真实调度器、执行日历、进程隔离、噪声模型和双后端集成尚待后续步骤。参数及安全锁止继续是合成、项目选择、未校准模型，不赋予医学或工厂认证解释。

## r2 有限修复及实际检查

PR054 仅授权修复发布后审阅的三项 P2；r1 的真实批准/发布和后续审阅分别见 LOG041/LOG042。事件模块、对应测试及必要说明/治理记录为本轮全部变更；观测实现、S05 规格与示例、S06 契约、S07 数值模型、依赖及 CI 均保留。

| 问题 | 修复与回归 |
| --- | --- |
| F01 恢复期间取消 | 识别 restore 与挂起 work；运行/暂停 restore 都可返回恢复尾部；传回 committed_tail 保留边界和 restore 序号，完成后不恢复 work；拒绝无关并行阶段、跨组尾部；后续 work 故障仍按取消规则放弃重做 |
| F02 资源依赖过宽 | 当前阶段主动角色/固定保持资源与准备失效独立判断；CUT/ASSEMBLE/WELD handoff 忽略已释放机器人；align restore 忽略已完成 feed；必要人员/工装故障仍阻断，reset 忽略已释放运输人员/目标 |
| F03 浮点时钟 | 前向时钟比较接受 15 组声明完成时刻；相邻更早时刻、超剩余量和真实倒退仍拒绝，相邻较短净推进不提前完成；S07 cap 未放宽 |

最终标准入口在项目与独立 wheel 环境各通过 137 项测试：原 126 项加 11 项事件回归（事件 40、观测 17，其他 80），Ruff、格式、锁、sdist/wheel 构建及依赖检查通过。测试数按不同测试方法计，不把两个环境重复计数。测试新增后先对旧实现执行，39 项事件测试报告 5 个失败与 10 个错误（含子案例及旧 API 缺参数），保留完整输出；三项问题修复后针对性检查通过，补齐取消后再次故障的回归后再执行标准入口并通过。

本轮不宣称完整事件内核或全输入正确性。committed_tail 是可信调用方保存的进程内结果；取消时间不在旧 S06 快照内，本轮没有扩大 Schema。真实执行日历、阶段完成/释放/清场及原子资源获取仍须 S09 集成。有限修复不包含上传批准，r2 的远端 CI 须新快照获批推送后核验。
