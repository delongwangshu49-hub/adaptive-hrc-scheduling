## 实际诊断与修正

初次命令执行器环境初始化失败，未运行仓库命令；后续使用已核验 PowerShell 7 执行通道继续。首次只读 Git 树查询的未引用花括号被 shell 解析，命令失败；改为字面引用后核对正确基线，未改变 Git。

首轮 15 项回归中一项测试错误使用夹具名，修正为配置实际 ID。扩展回归首次错误使用 T0 的 W1 引用结构实例人员，修正为结构配置 H1；原失败日志保留。Ruff 首次发现新增文件 import 排序问题，已整理。自查补齐废料接收空间锁、已开始交接目标保持、修复后的停止资源释放、故障人员保护休息、缓冲预留的故障依赖及日历失败原子性；对应回归保留。未覆盖或改写旧发布日志。

首次封存检查发现本步初始枚举漏掉旧测试仓库的 35 份隐藏 Git 元数据；这些文件已有 S08 历史摘要，按该摘要补核，保留最初枚举和实际失败日志，没有将当前状态伪作起始证据。

初版公开扫描将 HTTPS 链接中的字符片段误判为盘符路径；定位误报后收紧匹配边界并核对正反例，实际失败日志保留，未删除合法来源链接来规避扫描。

## r2 两项有限修复与检查

发布后审阅的 102 项交付/批准/远端检查和新副本 169 项既有测试通过，但独立反例确认两项 P2。S09-AUDIT-01：源夹具故障且 release_allowed=false，正常吊装仍放走工件；S09-AUDIT-02：反复舍入的剩余量导致提前一个浮点时刻完成或合法推进报错，并使同一故障在分段/不分段执行时得到不同状态。r1 已发布事实保持，不能以原测试通过否定反例。

r2 统一正常吊装的启动、运行中故障和源位释放依赖；events.py 仅扩展基于实际保持锁的源位依赖，不恢复已被否定的全绑定组故障阻断。阶段与清场净量采用每次开始/续作的日历锚点和精确有理比例，完成由已保存边界决定，S07 积分与严格 cap 不变。

新增 `tests/test_execution_repairs.py` 的 11 项回归覆盖：定位前/挂索前源夹具故障；定位/挂索中故障、保持原位与暂停净量、修复后续作；允许解锁的标志；未持有同站工装不阻塞；rig 恰好完成/完成后故障不影响 move；两组原分段反例；分段/不分段故障后的净量、中断和续作一致；精确完成先于同刻故障；六组固定种子分段的相同净量；清场暂停时正剩余时间一致。时间状态和故障次序使用严格断言，既有起点浮点表示下的半段时长仅用 1e-12 核对。

标准 CPU 入口在项目和独立 wheel 环境各通过 **180 项测试（原 169、新增 11）**，Ruff、格式、锁文件、依赖兼容、sdist/wheel 构建通过；原 T0 28 阶段手算与 F3 汇合回归继续通过，原示例摘要无需改写。

修复前失败证据保留。初版新清场测试误用不存在的原料 ID，改用声明的 J1.C1.raw；首轮修复后测试又把浮点起点下的半段净量断言为精确 .5，改为数值容差核对，完成边界与故障分类仍保持严格判定。两次诊断及后续通过记录分别留存，不覆盖旧证据。

## 限制

本证据覆盖自建确定性功能案例，不能证明任意实例无死锁、任意浮点分段一致、工业可行或 A/D 效果。本轮 r2 尚无远端 CI、Isaac 生产验证、调度优化、CP-SAT 或性能测量。静态资格、工时、恢复率和锁止仍是合成/未校准假设，无人体安全证明。

等待状态明确指出需要派工、清场或修复；未实现通用死锁搜索。清场固定首个声明合格 Q，可能等待而不改派。S06 快照之外还有 feed/清场/承诺尾部等内核状态，不能单独将 snapshot 当作恢复检查点，详见 [执行说明](../model/execution.md)。
