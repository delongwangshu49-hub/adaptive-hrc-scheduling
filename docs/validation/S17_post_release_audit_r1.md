## F1 / P2：自动初解没有纳入已承诺时隙

位置：`src/adaptive_hrc_scheduling/algorithms/static_lns.py:43`。构造原TINY_UNARY域，固定H模式，承诺 **A=[1,3)**；完整 **A=[1,3)、B=[0,1)** 经独立检查合法、目标3。不提供initial时，initial()直接对fixed_instance调用普通rule_schedule，没有将committed作为固定时隙加入生成条件；生成A=[0,2)、B=[2,3)，然后verify正确检出COMMITMENT_CHANGED。结果是 **WAIT / NO_LEGAL_INITIAL / best=None**，原因同时含FEASIBLE和COMMITMENT_CHANGED。

给同一输入显式提供上述合法完整初解，search返回FEASIBLE/目标3，承诺保持。这证明无解并非承诺本身不可行，而是自动初解路径遗漏约束。当前实现不会实际改写承诺，但可行的滚动/冻结时隙输入会失去可用初解。既有测试都将committed与完整initial一起提供，未覆盖此组合。

建议有限修复：让自动初解按固定承诺生成合法补全；若该输入组合确不支持，须明确接口前置和退出类型，而不是接受committed后生成必然不相容的普通初解。须保留承诺不可改写及独立检查，并增加已知可补全/确实不可补全/预算失败控制。**本轮未修复。**

## F2 / P2：生产自动初解未过滤已观察拒绝父操作

位置：`src/adaptive_hrc_scheduling/algorithms/production_lns.py:106`。用公开ProductionBackend.dispatch的preflight回调合成一次PATH_BLOCKED/DEFERRED，不修改_admit、执行准入或独立检查器；过去决策和事件前缀均有效。已观察拒绝父操作为 **PRODUCT-1.KIT.U1**，将fresh planning_input的完整operations和这个rejected参数交ProductionProblem。

initial()仅给choose传excluded_operations，未像自身_choose()或现行production_loop一样先过滤value.operations；原choose的静态候选集合不按这个参数过滤。因此初解再次为 **PREPARE:PRODUCT-1.KIT.U1**。本步verify正确拒绝REJECTED_PARENT，但search返回 **WAIT / NO_LEGAL_INITIAL / best=None**，没有继续取另一个合法基线或显式Plan等待。

单产品控制：只过滤该父操作，原choose返回WAIT，本步独立核验合法。双产品控制：同一当前前缀/配置/已观察拒绝，过滤后返回 **PRODUCT-2** 的准备候选；本步verify合法，实际轻量dispatch为STARTED，完整新前缀的独立执行与决策审计均PASS。这是合成命令级端口拒绝/准入控制，不冒称真实Kit通行或全链完成。

原production_loop在调用规划器前已过滤operations，故发布的正常早期12窗口见证避开了此问题；不能从它们通过推断公开适配器可直接正确处理fresh planning_input+rejected。建议使初解/修复/原驱动拒绝过滤口径一致，验证有效拒绝后的替代动作、只有合法等待、正在执行/续接及既有历史不变。**本轮未修复。**
