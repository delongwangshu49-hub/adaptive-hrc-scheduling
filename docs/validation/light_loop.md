# S12 轻量反馈闭环验证

版本S12-1.1；2026-10-02；合成功能验证，不是工业标定或算法收益实验。当前状态见[S12步骤卡](../steps/S12.md)。冻结D01—D06、G1/G2/G4/G5/G6/G7缺口、默认HR禁用、J2同产品双框驻留及FIX-J2独占均保持。

## 实现与信息边界

`control/light_loop.py`的可信适配器`capture`从C05取当次完整、零延迟观测，投影已释放产品、活动、BOM/材料和所需资格；`ObservedState`白名单仅含当前attempt、running、具名人员状态、驻留、锁、质量、故障、工艺释放、服务及已发生事件。未释放产品的静态规格和材料事件不进入控制器；HiddenScenario、种子、事件/随机游标、未来事件队列均不进入Feedback。该边界是进程内API隔离，不是抵御恶意Python代码的安全沙箱。

`choose`只接受Feedback、公开Options、序号及先前事件ID，复用S11合法候选枚举和EDD/SPT/当前合法最快模式排序。每次生成一条当前可执行提案，或休息、取消清场、等待、停止；默认EDD。计划始终为INCOMPLETE，predicted_ready未知，不冒充完整可行排程。尚未派工的部分每轮重新选择；已开始活动的模式/工作单元/角色、实际驻留、质量和搬运承诺保留在C05，控制器没有写回快照或撤销接口。探测仅操作观测副本，静态已校验配置缓存不含情景或运行态。

`run_loop`保存执行器、隐藏情景和显式合成环境；调用次序是实际反馈→采样→选择→执行→回执→再采样。每条Turn记录观测ID/版本/时刻、触发原因、提案、实际接受或拒绝、产生的实际事件ID、动作前后实际事件计数及执行后版本/时刻。触发原因保留具体EXTERNAL事件种类。调度不导入静态整条生成器，也不使用预生成计划回放。

C05的`advance(..., stop_on_feedback=True)`在实际事件产生后提前返回；默认False保留原推进语义。控制器等待截止仅由公开轮询间隔、窗口、已知工作/服务结束、工艺等待、休息和日历边界决定。未来事件能在实际发生时唤醒，不能影响发生前动作。默认轮询1h；合成质量延迟在实际检查完成后计时，于其后的第一次唤醒交付，可能离散化延迟，不能解释为连续测量精度。

## 等待、取消和未完成

- 人因保护、班界、占位、故障、材料和质量阻塞均可合法等待；没有为解锁伪造RECEIVED、PASS或腾位。未知质量保持HOLD；硬件修复不自动恢复被中断的工艺资格。
- 活动运行中取消时仍完成不可撤销安全尾段，之后不能新派该产品工作；满足已有资格、位置/载荷/人员和占位门后单独执行收费清场。整模块清场到Q1为CLOSED_WITH_CANCELLATION，绝非READY或交付收益。原料/未装配组件缺清场方法时保持CANCEL_PENDING及真实驻留。
- 悬吊/搬运及清场紧急HOLD不继续推进、不释放负载或锁，返回真实未完成前缀。质量失败不自动返修；本步未增加返修策略、交班策略或应急恢复路径。
- 预算或窗口截止返回已发生前缀。若预算在t=0耗尽，额外记录一次不派工的终止观测等待，至首个实际反馈或min(轮询间隔,窗口)，以取得S10正时间共同窗口；不会因预算退出撤销已开始工作。该等待不计为继续调度，可能使Turn数比max_decisions多1。
- COMPLETED要求全部配置产品达到READY/RECEIVED；有取消且均已闭合则CLOSED_WITH_CANCELLATION；其余UNFINISHED。实际或决策审计失败为INVALID_TRACE。未找到动作、窗口/预算耗尽不表示数学不可行。

## 独立核验与因果证据

每次`run_loop`均调用S10 `check_run(config, actual_snapshot)`，从实际原始事件重建约束、全员区间、占位与评价集合，包含未完成和取消。默认报告保持S10-1.1，不把S11静态候选绑定套用到动态轨迹。S12 `audit_decisions`另核验提案与实际启动/休息/清场事件对应、命令ID/配置/版本、可见产品、事件前缀、时序与等待截止；它不调用控制器或执行器准入谓词。

S10物理PASS不等于动态策略非预知证明。35项专项中明确包含：重复输入/同随机流的同历史动作一致；未来故障、情景种子和质量结果变化不提前影响派工；未释放订单不出现在可见配置；故障/材料反馈导致CUT在4h恢复后等到4.5h合法班界；实际RECEIVED腾出OUT1后第二产品可以MOVE-OUT，而缺接收时合法阻塞；质量FAIL不派下游COAT；取消两种出口及搬运故障真实前缀。

正反核验含畸变命令配置、观测事件ID、版本、角色、缺失实际启动和丢失决策记录；S10在执行器dispatch被禁止调用时仍独立拒绝伪造驻留并接受正常轨迹。测试也覆盖不改观测、角色/模式/驻留承诺、HR默认禁用、无自动质量、窗口端点READY与预算退出。有限构造例不能证明任意输入的全部策略性质或可行性完备性。

[11条输入](../../examples/light_loop/cases.json)与[实际摘要](../../examples/light_loop/summary.json)提供完整模块两变体、默认资格HOLD、未来订单、故障修复、三阶段材料反馈、质量延迟/FAIL、整模块取消清场、原料取消HOLD及短窗口。完整观测/决策/实际轨迹仅写本地指定目录；相同可见配置按内容摘要去重，观测历史事件由event_ids在实际trace中还原，保留所有实际载荷。

两变体正常READY为147.005h和147.5075h；故障修复和材料反馈例均149.5h；质量延迟例193h；未来订单例两产品147.005h/245.5h且最终RECEIVED。这些是合成回归数值，未与静态S11或其他算法比较收益。默认资格、质量FAIL、原料取消及短窗口均保留UNFINISHED。

初次命令运行器沙箱初始化失败，经受审PowerShell7通道恢复；首次新增包未重建导致导入失败，其后休息返回契约接入错误也保留。首轮25项专项5失败：一项实现问题为t=0预算退出没有正评价窗口，另四项预期错误分别为故障注入非当前搬运设备、使用错误清场事件名和两处忽略4—4.5h班界。修正后25项通过；未放宽生产约束、删除负例或抹去失败。最终CPU和生成物核对的实际数量/时长见步骤卡。

## 限制

当前控制器要求可信完整零延迟观测；B的延迟/缺失/噪声稳健性、异步Isaac消息、LNS、CP-SAT、正式A/D/B/C实验及S13—S28尚未实施。无一般可行性完备保证、最优性或墙钟实时保证。反馈源是明确标注、只允许SYNTHETIC_TEST_ONLY配置的测试环境，质量/释放及资格PASS不是工业证据。S11静态接口S11-1.1与S10候选报告S10-1.3保持。


## r2有限修复：决策账与实际前缀绑定

针对AUD-S12-01，`control/ledger.py`按真实事件顺序复用S10的独立重建器，核对每轮已释放配置、完整可见事件前缀、产品/组件/材料/attempt/running、驻留、锁、质量、服务、工艺释放及人员状态。人员F/E/峰值来自已经由S10核验的实际积分区间；休息截止由已发生休息事件核对。事件计数是实际前缀切分证据，须与逐轮事件ID、连续时序、前后边界及最终轨迹覆盖相符，不能自身作为真实性结论。版本由实际积分tick、成功命令/服务和手动外生反馈重建；情景内反馈计入所在tick，不重复增加版本。未来订单的隐藏材料事实到该订单释放后才进入可见历史。

针对AUD-S12-02，瞬时READY/COMPLETED也核对适用模式、attempt、unit、角色及实体；不能只靠同产品实体绑定。针对AUD-S12-03，显式REST_START/CLEANUP_START必须唯一对应正确类型、接受状态、参数、回执和时刻；最终覆盖集合反向检查全部显式服务。自动PROTECTIVE_REST和外生反馈保留各自来源，不要求虚构调度命令。

新增10项方法覆盖上轮反例、旧账缺边界、观测人员/配置/已释放订单遗漏，以及隐藏材料释放前后；屏蔽choose/capture/准入接口时独立审计仍可接受正常证据。新增计数不改变选择/执行，11例r1对照及实际验证见步骤卡。本轮首个Ruff检查发现一处import排序问题，修正后随完整CPU重新检查，原日志保留。

独立重建复用的是同包内S10审计器，不是第二套物理规则实现；必须与最终S10 PASS联合解读，不能单凭空决策发现列表认证任意物理轨迹。当前控制器仍限可信、完整、零延迟观测。旧r1未携带真实边界计数的账返回`INCOMPLETE:ACTUAL_BOUNDARIES_REQUIRED`；畸变/不可读证据返回明确INCOMPLETE发现，不伪造边界补齐。r1实际发布事实不因接口严格化而改写，历史证据保留。
