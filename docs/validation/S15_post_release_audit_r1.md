## 审阅发现

### F1 / P1：P1走行全程排除整个叉车

`production_navigation.py`的`walk_obstacles()`对所有P1走行排除FORK-01，`sim/isaac/scene/production_port.py`的`check_path()`有相同整车排除；例外不检查登离车阶段、起终点关系或具体接触部件。

在原配置中，构造从CONTROL-P1到CONTROL-SUPPORT-MEP-RECEIVE-P1、经过叉车后挡板中心(6,4.3,0)的WALK路径。后挡板范围x[5.35,6.65]、y[4.25,4.35]、z[0.2,1.8]，人员扫掠碰撞成立。未绕过或替换执行准入，命令仍STARTED并完成，独立审计PASS。这证明接口可接受非法人员路径，不等于已经证明历史16例走过该路径。USD端的相同例外来自代码审阅，本轮未在Kit运行此反例。

修复应限制接触例外到批准的部件、位置与阶段，保留其余车体障碍；新增合法登离车正例及非登车穿车负例，重验受影响路径。不得通过缩小人员/车体或取消碰撞来消除问题。

### F2 / P2：独立审计漏检WALK中间路径碰撞

`production_checker.py`在STARTED重建中检查带设备路线、产物及支承碰撞，没有人员WALK的逐段障碍检查。`validate_service()`的端点、参数和场地边界校验不能替代路径扫掠。

E1路径穿过CUT1时，正常执行器拒绝DECLARED_WALK_COLLISION；本地探针仅在生成非法历史的派工阶段替换执行端碰撞返回值，恢复真实函数后，未经替换的独立检查器仍给出PASS。该实验说明检查器不能兜底执行错误，不表示正常执行器允许CUT1穿越。

应从独立重建状态检查人员身体包络、整条路径和受限接触例外，加入定位到规则/人员/命令的篡改反例。执行器与检查器共同调用错误几何谓词不能构成独立正确性证据。

### F3 / P2：逐决策比较未审计观测—计划—回执关联

`compare_production_chain.py`只对两端决策JSON逐字段比较；后续`check_run()`输入仅含事件和最终状态。`verify_production_chain.py`保存观测ID、版本和采样时间等摘要，没有完整可见观测或可独立验证的前缀关联。

复制真实未开工取消的双端证据，只将两端决策state_revision、sampled_h改为999999，observation_id、receipt_id改为不存在的ID，配置/事件/最终状态保持。比较程序退出0、整体PASS、两端审计PASS且无finding。

应独立检查授权观测及已交付事件前缀、运行/配置身份、版本时间、计划命令和实际回执；缺失或无法关联必须输出INCOMPLETE/INVALID。此发现不证明现有规划器实际泄漏未来信息，而是说明当前证据检查不足以排除错误关联；旧S12决策审计不能自动覆盖新生产格式。

### F4 / P2：WORLD故障与修复缺少独立前置条件核验

`production_checker.py`对FAILURE直接加入故障集合，对REPAIR直接移除，未独立检查合法设备/通道和已故障前提；执行器分别有UNKNOWN_FAILURE_RESOURCE与NOT_FAILED保护。

将合法初始故障事件及末态故障集合一致改为不存在的BOGUS，审计PASS；将其改成未故障FORK-01的REPAIR并保持空故障集合，审计仍PASS。两种输入都被正常执行器拒绝。应补全外部事件对象域与状态迁移前提，不能仅凭日志末态自洽认可外部事实。
