# HRC Workbench v1.4.0 local candidate guide

Application 1.4.0; core library 0.1.0. Local native acceptance covers direct selection, order/resource linkage, dual export, safe stop, saving, observed exit and read-only reopening. This candidate is not published. See the [native validation record](../validation/UX_v1.4.0_native_validation_r1.md) for evidence and remaining coverage.

## Start and diagnose

Extract the entire portable ZIP and retain the app folder beside HRC-Workbench.exe. Choose Start full simulation, review the product template, initial quantity and backend, then Check and start. Advanced parameters include simulation rate. Isaac is the default and requires local Isaac Sim 6.1, PowerShell 7 and a writable ASCII results path.

CPU mode, the data example and historical sessions are explicit choices. They are not live Isaac scenes. The home image is a real static capture from an earlier session, not the state of a new run.

Settings & help → Diagnostics lists failures first and folds passed checks. Quick checks inspect startup prerequisites; full checks include integrity, dependencies and logs. Follow the exact repair paths and retain the original error. If the interface cannot open, use HRC-SelfCheck.cmd. Inspect local paths before sharing reports.

## Use both views

Isaac remains on the left and the schedule on the right. Operate, Demonstrate and Analyze change the ratio while preserving both views. Minimum client size is 1280×720. Forms and receipts open below the work area; diagnostics and help open beside it, with internal scrolling.

The interface uses neutral charcoal backgrounds. Thin blue-gray outlines identify selection, muted green filled bars show actual work, and pale gray outlines show plans. Physical parts link to work through declared operation targets. Multi-selection retains all related objects; empty or unmapped selection clears stale work. Selection does not move the camera. Use Focus object and Previous view explicitly. Registered products that are not yet visible cannot be focused.

Actual clicks on equipment, people and materials, forward/reverse rectangles and blank clearing were observed. The available automation API cannot hold Shift/Ctrl/Alt while injecting mouse input; these combinations have mapping checks but are not claimed as native mouse acceptance. Other computers and multiple monitors remain untested.

## Navigate and change work

Production now shows the current production interval and scrolls to related work. Full plan fits the entire plan; Selection fits related work. Search finds processes. View & export contains filtering, resources, product overview, comparison, name-column width and exports. Scroll vertically; Shift-scroll pans time, and Ctrl-scroll zooms. Expanded hit targets for short work do not alter recorded durations.

New order and Urgent order are direct commands. People contains arrival, departure, absence and return; Orders & equipment contains due-date/priority edits, faults, repairs and cancellation. Review business parameters before confirmation; expand technical identity when needed. Submission retains its original receipt. Querying does not create a new request. Manual rest remains explicitly unavailable.

ACCEPTED means durably received; APPLIED means the business change took effect. Neither means production started or completed. During urgent replanning the last verified plan remains visible. Do not resubmit because a calculation is taking time. A plan is adopted only after execution and causal audits and actual/frozen-prefix checks. Scene changes follow actual production state.

This version restores safe immutable reuse under native timing wrappers and bounds geometry caches to one replay. It does not reduce constraints, shorten simulation or omit verification. Fixed-input CPU timing and native end-to-end timing are reported separately. A 60-second result or 50% reduction is not guaranteed.

## Export and finish

View & export provides dual-view or schedule PNG/PDF, filtered CSV and full JSON. Dual export requires live Isaac and records separate scene/data capture times.

Use Safe stop, wait for safe work to drain, complete saving and actual process exit. A disappearing window does not establish success. Ended sessions show a checksum-verified final capture with its timestamp when available. Older sessions without matching capture metadata show an explicit absence. Read-only reopening does not start Isaac or provide 3D replay.

The prior capture/exit repair is preserved and was retested on this candidate. Owner E12 acceptance, teammate-machine checks and existing research-performance/industrial-qualification limitations remain.

Same-ID return now uses the person’s last verified location; unknown locations must be resolved before submission. Switching view level or filters resets the list to the top. Final Isaac and workbench exits were both 0, and all 79 archive files remained unchanged after read-only reopening. The urgent order was registered and its plan independently verified; its later physical start was not reached before safe stop.
