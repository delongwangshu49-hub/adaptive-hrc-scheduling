# v1.0.1 — First official workbench release

[English](v1.0.1.md) · [简体中文](v1.0.1.zh-CN.md) · [Downloads](https://github.com/delongwangshu49-hub/adaptive-hrc-scheduling/releases/tag/v1.0.1)

This release brings together the Windows portable workbench, the reviewed English and Chinese reports, and the existing steel MiC production examples. The main locally verified workflows are usable. Bugs and unknown issues may remain; further work is being planned to improve responsiveness and address outstanding gaps.

`v1.0.1` identifies this first official application delivery. The embedded Python library retains its existing `0.1.0` package metadata. The research results and earlier milestone tags are preserved.

## Download and run

Download `HRC-Workbench-Windows-x64.zip` from the release, extract the entire directory and double-click `HRC-Workbench.exe`. Keep the adjacent `app` directory. The ZIP is 340,032,822 bytes and contains 8,524 files. The launcher is unsigned and uses Windows .NET Framework 4.x.

The package includes Python 3.12.13, PySide6 6.12.0, Qt WebEngine 6.140.0, OR-Tools 9.15.6755, the Gantt frontend, SR-W1/SR-W2 production inputs and a read-only CPU archive. CPU mode requires neither a separate Python installation nor Isaac Sim.

1. Open **启动配置 (Launch configuration)** and start the default single-product SR-W1 CPU case.
2. Initial planning and independent Gantt replay each take time. Use **便携设置与示例 (Portable settings and examples)** to open the bundled archive or choose a results directory.
3. Use **安全停止 (Safe stop)** to finish a session and wait for the worker to exit. Use **打开会话 (Open session)** to inspect an existing session.

Results default to `%LOCALAPPDATA%\HRCWorkbench\runs`. Startup diagnostics are in `%LOCALAPPDATA%\HRCWorkbench\startup.log`; worker logs are in the individual run directory. Attach the version, reproduction steps, selected backend and relevant logs when [reporting an issue](https://github.com/delongwangshu49-hub/adaptive-hrc-scheduling/issues).

### Optional native 3D

Install Isaac Sim 6.1 and PowerShell 7 separately. In portable settings, select the Isaac root containing `python.bat` and `VERSION`, choose a writable ASCII-only results path such as `C:\HRC\runs`, and select **Isaac / Kit**. The build machine used **6.1.0-rc.26**. Other machines and versions still need validation.

Native screenshot capture failed with a Chinese results path on the build machine. The launcher checks this condition before starting Kit and puts Kit rendering caches under the selected results directory. CPU mode and archive viewing support Chinese paths. NVIDIA runtime components and assets are obtained separately.

## Known issues and validation scope

| Area | Current scope |
| --- | --- |
| Responsiveness | Planning and independent Gantt verification remain slow, with limited waiting feedback. The original 2 s source-age target is unmet; sustained 4 Hz and 10/s–50/s load qualification remain unestablished. |
| Dynamic production | Original E20 r14 received 1/4 products at its observation end. Its approved split-scope closeout remains in effect. WIP cancellation and J3 HOLD residual completion remain incomplete. |
| Acceptance and native runtime | Testing on other machines, long runs and E12 owner-operated acceptance remain pending. K02 shutdown repair passed within its tested scope; historical K01's root cause remains open. |
| Other boundaries | Manual REST is unavailable. The fixed study establishes no general ADAPTIVE delivery advantage. Industrial qualification remains open, some currency policies are missing, and the pinned frontend toolchain retains its recorded Vite advisory. |

The [historical status](../public_results/status.md), [failure records](../public_validation/failures_and_repairs.md) and [toolchain advisory](../public_validation/toolchain_advisories.md) retain the detailed evidence. Investigation and planning are underway; proposed improvements are not included in this release.

Packaging validation passed 23 frontend and 41 targeted Python checks, plus Ruff. The real EXE launched a CPU session with development tools removed from PATH, displayed its Gantt and saved safely with worker exit code 0. The bundled archive replay consumed all 535 delivered packets and checked 1,023 full-plan intervals and 20 actual-prefix rows. A relocated extraction with Chinese characters and spaces opened read-only and exited with code 0. External Kit validation exercised native frames, screenshots, Gantt and safe saving on an ASCII results path. These are build-machine checks; E12 still requires the owner's own continuous operation.

## Source and rebuilding

The portable sources are in [`desktop/p051/portable`](../../desktop/p051/portable). Build on Windows x64 with PowerShell 7, uv 0.12.3, Node/npm and the Windows .NET Framework x64 C# compiler. The recorded build used PowerShell 7.6.5 and Node 24.20.0. Locked Python and npm dependencies are installed into a separate build directory; frontend assets are rebuilt there.

```powershell
& ./desktop/p051/portable/build.ps1 `
  -BuildDirectory 'C:/HRC/build-v1' `
  -ArchiveDirectory 'C:/HRC/verified-cpu-session'
```

Use a fresh build directory and a verified CPU session. The supplied archive is a read-only viewing subset, not a complete production-run evidence bundle. The older frontend `dist` in source control remains a historical artifact; the README's source-launch instructions rebuild the current frontend.

Project code uses [MIT](../../LICENSE). Bundled components have their own [notices and source links](../../desktop/p051/portable/THIRD-PARTY.md), also provided inside the ZIP.

The initial `v1.0.0` tag and its CI failure remain in history. This revision updates a legacy test to check the complete portable worker command; the ZIP and both PDFs are unchanged.
