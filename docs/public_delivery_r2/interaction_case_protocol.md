# E01–E24执行与独立见证协议 r2

2026-10-22；`P03.3-E-PROTOCOL-r2 / PROTOCOL_READY_NOT_EXECUTED`。逐案例输入、触发、期望、拒绝、证据及核验见[24案例表](interaction_case_protocol.tsv)，原r2需求/案例表保持PLANNED状态。此处“执行”均指未来获准P04–P08后的操作规程，本轮仅核对协议。

## 共同初始输入与证据

每次先生成受控preflight包：完整新源码清单/模板与资格注册表、RunSpec、C0、profile、材料计划、成本政策及SHA256；新建run_id/epoch=0，冻结后才开始。P03.3输入配方见[e20_input_recipe.json](e20_input_recipe.json)，不能把契约例子的重复a摘要当真实来源。当前不生成冒充已实现消费者的RunSpec；P04完成后按配方解析真实注册表，所有解析值、hash、能力和上限齐备才允许P05见证。缺输入记PREFLIGHT_BLOCKED，不能临时换模板或用预声明订单池。

证据包统一包含spec/C0和源码身份、逐请求原文/摘要及单调提交时间、持久回执链、目录Delta与提交标记、物料/场地/资格与场景绑定、完整事件/命令/真实读回、每个观察及完整前缀、候选/采用/承诺/缓存变化、业务结果、人员区间、两图采样封套/截屏/导出、最终SessionFinal及实际进程退出。未执行字段为NOT_EXECUTED，不填写PASS。来源为MANUAL_WINDOW或AUTOMATION，负责人实际操作另签OWNER_OBSERVED，自动测试不能代签。

独立核验者从C0+连续Delta重建目录，从原事件/读回重算资源/前序/物料/产品接收、人员F/E与费用，从观察前缀重建可见事实并核决定/采用，从原始区间核两图与导出。仅相信GUI摘要或复用同一个展示计算函数不够。完整链可共享多案例，但每条条件都须有独立定位；24案例不等于24次长运行。

## E20唯一主会话与阶段门槛

使用一个真实Kit worker/engine、一个run_id、epoch=0；启动后不reset、不restart、不清状态。初始仅ORD-BASE一单1件SR-W1/v1，15名原始人员；新单ORD-NORMAL、ORD-URGENT与人员W3不在初始/历史目录。NORMAL数量2、URGENT数量1，使累计登记件数1+2+1=4；WIP候选上限3，空间/库存仍按真实配置约束。量产上限不是本协议保证。

| 阶段 | 触发与窗口操作 | 通过门槛/必须保存 |
| --- | --- | --- |
| A 原单启动 | 实际读回证明ORD-BASE至少一条命令已STARTED；观察仍有后续未承诺可调任务 | 保存命令/读回/观察/前缀和未承诺集合；未满足不得点击新单；不以预览计划代替实际开始 |
| B 普通真新单 | 在持续生产窗口提交ORD-NORMAL，数量2，交期2300h | ID首次登记、完整任务/BOM/稳定产品ID生成；Delta提交、到达观察、物料/场景等待及后续就绪有据；原单前缀/进度保持 |
| C 真新急单 | B已APPLIED且到达观察，原单仍有可调后续任务；窗口提交ORD-URGENT数量1，due=t_anchor+96h，t_anchor为最终确认前所选已验证观察的sampled_sim_h | 到达前观察/候选无该单；到达后真实急单紧迫性影响至少一项未承诺安排/模式/班组或顺序，实际采用并有后续执行；保留承诺 |
| D 计划减员 | C的影响与采用已落证据，原单仍有后续可调任务；窗口提交W2 PERSON_DEPART | 立刻禁新增分派，DEPARTURE_PENDING与DEPARTED分列；只用合法停点/已有受限交接服务，不强行打断危险动作；保存持有/班组/连续F/E |

门槛未出现、预算先到或急单无真实影响，记E20 NOT_MET/CENSORED并保留整条原链；不能放松门槛、重写交期或拼接另run的结果补通过。P04可在独立开发身份校准竞争窗口/参数；正式见证前冻结配方修订/源码/时钟/预算，失败后重试另立run，旧失败保留。急单影响核验还须在**相同已观察状态**用已实现决策接口作离线对照（NORMAL优先级对照与URGENT比较），保留候选/目标输入/采用及至少一项改变，不能只凭“发生一次重排”或普通漂移认定紧迫性生效。离线对照不进入真实会话、不修改真实轨迹。

初始/普通交期2500/2300h、急单相对已验证提交前观察96h、会话截止3000h均为候选协议值；实际耗时/方法profile与材料计划在P04有限校准后事前锁定。基准SR-W1的原交期/初始集合只作配方来源；P04按本配方覆盖初始订单后另生成C0及其摘要，绝不改原配置。成本候选为每个受支持初始/新人员模板唯一10 MODEL_UNIT/h，完整费率表由preflight物化并冻结，不冒称实际工资。提交前把expires数值固定为t_anchor+24h，若交期或资格到应用时已过期按原契约拒绝。所有接纳期望版本取最新已验证观察/worker握手；STALE则新请求ID和序号重新提交并保存原拒绝，内容不同不得复用旧ID。已受理重试只查原ID，不改变payload或SceneReference。

## E21、E23与受控分支

E21可共享E20：逐件保存count_registered单调≥4、count_open/queued/wip及场地/库存；至少一次真实WAITING_SPACE/队列及之后释放实例化，全部4件最终曾有合法场景绑定与执行。若E20配置没有实际排队，就不能顺带宣称队列门槛已验；另做有界容量例。超过lifetime/open/queue配额为整请求拒绝，WIP满对已登记单等待，不能部分接纳quantity或放宽场地。

E23的空队列等待另用CPU有界同会话：一单完成后仍OPEN，推进至少1h且跨一次日历边界，再提交真新单；WAIT/REST/OFF_SHIFT、连续F/E与presence成本可独立重算。另有关闭前已ACCEPTED未来新单/到岗的fence例，关闭后到期仍应用或合法拒绝并终结；STOP/WINDOW/WALL截尾是单独反例，不伪称E20成功。E20本身无需强造暂空队列。

故障→维修可以共享一个受控Kit例（E04/E05），触发设备/阶段事前冻结且必须有实际故障读回和后续恢复执行；取消用另一例（E07），核剩余订单/尾段/残余；突发缺勤→返回用第三例（E17/E15返回部分），保留安全HOLD/持有与同ID连续F/E。这些可承接同身份充分历史并对新入口补必要片段，但不得把取消残余算进E20的全部产品正常接收。H/HR高疲劳四机制和五情景两方法覆盖按P01用途矩阵另核，不因共享案例省掉尚缺技术覆盖。

E12由负责人在P08/P09实际完成无需代码/内部JSON的启动→新普通/急单→增减员→解释两图/原因→关闭保存；P05自动化或操作者见证可验证软件，但不替代负责人操作。E19/E24使用布局/容量矩阵，缺硬件条件标UNAVAILABLE；未达到阈值如实记失败。

## R01–R05有限修订的执行口径

本版仅修订P03.3设计与参考核验，P03.2-CONTRACT-r3保持原字节。旧r1及审阅/失败另存。

最终确认前选取最近已验证的交付观察，核run/epoch、观察ID、完整前缀、目录/状态版本及sampled_sim_h，记为t_anchor。把急单due_sim_h=t_anchor+96、所有变更expires_sim_h=t_anchor+24先物化为有限数值；普通单due_sim_h固定2300，原单2500。预览显示最终数值及观察来源，确认后生成完整ChangeRequest并计算摘要，再保存/发送。观察和物化说明另写证据记录，与请求摘要关联，不向原schema添加字段。

收到请求的actual received_sim_h另列，延迟只能减少剩余余量，不顺延交期/有效期，也不改payload/幂等ID。版本陈旧或实际已过期依原契约拒绝；未接纳且明确终结拒绝后，操作者才可重新选观察、确认新数值并用新ID/新序号提交。UNKNOWN/已接纳重试只能查原ID和原摘要。立即请求仍省略requested_sim_h；不能把参考锚点误作立即生效时刻。

W2离岗使用精确枚举SAFE_POINT_OR_VERIFIED_HANDOVER，新W3引用/World/P05/People/W3；scene_reference仍不含实际catalog ordinal。入口/模板/资格与Kit读回就绪门槛保持。

E20参考判定只核该真实会话完整业务链及容量不越界，不要求其自身出现排队。E21另核至少4件累计准入、真实排队→合法释放/实例化及容量；可声明SHARED_E20并绑定同run/epoch，或SEPARATE_BOUNDED并保存独立运行身份。独立容量例不等于补接E20片段，也不强制再做一条四件全部接收长链。只有E21对应证据自身满足门槛才记覆盖，不能因放宽E20而把E21空缺记通过。

视图参考模型分painted_schedule与painted_proposal两个轴，旧painted_as不再作为r2格式。PLAN行须保持实际源schedule与方案proposal一致：未排、暂定和未来承诺均不可画为ACTUAL，候选不可画为ADOPTED。ACTUAL仅可来自FACT_PREFIX行，具有已交付事件/真实读回的引用且绑定所示前缀；画为FACT_PREFIX，不冒称新候选已采用。候选比较可同时显示独立保留的实际历史前缀，这个合法情况不因候选上下文被拒绝。参考字段是合成核验夹具，真实引用/前缀的完整独立验证仍留P06，不能把非空ID当作生产真值证明。
