# S20 实验协议候选 r1

2026-10-19；`S20-DESIGN-r1`；**PENDING_FREEZE / NOT_AUTHORIZED_FOR_FORMAL_RUNS**。依据 PR189 实施设计，不是负责人最终冻结。适用 `S18-SIM-A1` 仿真域；工业 G2 OPEN/NOT_ESTABLISHED。

## 研究问题与设计集

主问题：在相同生产规则、输出、布局/物流、人员/日历、cap 与搜索预算下，已有自适应联合、固定 H、固定 HR 和无观测更新四通道的交付、可行性、人因及计算成本如何变化，包括无益或反向结果？四通道共同驱动为 `SimulationJointPolicy`；不把 S19 OnlinePolicy 的性能/缓存能力混入该方法对照。

机器输入：[配置目录](../../experiments/configs/s20_r1.json)、[manifest](../../experiments/manifests/s20_r1.json)、[继承来源](../../experiments/manifests/s20_sources_r1.json)。配置是可重建描述符，绑定生成器参数、schema、准入与完整配置 SHA256；不是凭名称指向可变默认值。

所有实例来自原批准产品、BOM、生产/几何规则；2/3 产品只作为现有生成器的可解析配置，不据此宣称所有新组合已完整闭环通过。主集合为固定设计全集，没有随机总体抽样。生成、求解、分析种子分开：主集合外生情景确定，求解使用原调用序号，主描述性分析无随机种子；B 附录专用流另外声明。

## 共同生产规则与运行模式

保留 15 人资格/位置/日历、10 设备条目（含 2 工装）、J2/J3/FIX 关系、成品 B=2、cap=0.8、原路由/库容、材料谱系、工序停点及原所有者/承诺规则。H/HR 完成同一获批抽象输出；模式差异不能省材料、质量门、运输/准备/卸载或人因。固定模式仍可合法选人、排序和休息；无更新仅用锚点及名义演进评分，当前事实只作安全盾/时钟/回执绑定。禁止移除保护约束作为消融。

主统计运行 CPU、前端 OFF、零延迟当前事件前缀；源/配置/环境锁定后按 manifest 固定顺序、同机顺序运行，不并发计时任务。同一 pair 内方法顺序按方法表稳定顺序，运行序位置记录；本轮不宣称排除时间顺序对墙钟的影响。计算成本只作该机器和设置下观测；需要稳健性能比较时另预定平衡顺序重复，不能直接用一次墙钟认定速度优势。

真实 Kit 的角色为继承语义见证与后续已批准用例核对，不合并入 CPU 效应样本。S19A 资产、S19B 界面身份及已接受性能限制见来源表。界面演示、人工干预、截图/视频不充当统计样本。关闭/进程退出状态独立记录，缺证据为 UNKNOWN。

## 情景与预算的确切候选值

主测试所有订单 release=0，交期沿原配置（SR-W1 168h、SR-W2 192h；最终按描述符实际产品记录核对），窗口 `[0,720h]`，不得按结果延长。原 WV01 960h/840h 特例不纳入本轮主集合；满位/未完成在 720h 如实截尾。

- NORMAL：现有合成质量、到货与外部接收规则，未附加延迟。
- LATE_MATERIAL：实际首个原始 STEEL 批次 `PRODUCT-1.ST-B.01` 到货门限 12h；其余规则相同。
- LATE_RECEIPT：外部接收许可最早 480h；在此之前已 READY 仍驻留并产生背压。是否实际触发等待从日志判定，未触发不能谎称有效扰动。
- LOADED_FAILURE：沿现有 `loaded_failure=True` 的带载里程碑触发、修复规则与实际日志。它是**共同触发规则**，并非方法之间完全相同的绝对时刻；若未触发，单列 NOT_TRIGGERED，不能从 C 分母删除。

12h/480h 是本轮**待负责人冻结的合成情景候选值**，用于形成可区分的材料/接收等待，非工业分布或实测；本轮仅解析，不执行这些测试配置。生产工时、cap、速率、设备/容量不变。恢复方案超出现有规则时保持 HOLD。

主搜索预算：0,8,…,712h 共 90 个机会；每次最多 1 迭代、1 修复试次参数（初解亦计试次），累计 90 调用/90 迭代/180 试次；每次 120s，累计 10,800s，未来窗口 8h（尾部截到 720h）。整个驱动另保留 max_turns=20,000。此预算是候选研究资源上限，非总耗时预测，也不是 S19 5s/50ms 在线承诺。64 行名义累计搜索额度上限 691,200s；驱动/审计/序列化额外记录，不能把它当完整墙钟上限。

开发预算沿现有测试小例：1h 窗口，机会 0/0.5h，2 调用/2 迭代/4 试次，每次 30s、累计 60s、未来 1h。四通道最多 8 次搜索，开发执行父进程监测；若单进程超过 10 分钟，记录环境/预算疑点后终止，不扩容重试求好结果。

当前预算是协作退出：超时会记录并拒绝超额候选，不能保证硬墙钟终止。分别报告调用/迭代/试次、候选验证时间、累计搜索、全运行墙钟/CPU、超额与未用额。预算超额与审计失败分别分类；超额运行保留，不能进入“预算内收益”分母而不披露。

## D、B、C 与简化参照

D 保留核心研究目标，具体权重候选、归一化与共同尾部定义见 [范围决定](S20_scope_decisions_r1.md)。现有字典序四通道在人因指标上作描述不等于已完成 D 权重扫描。未实施新评分或改变 cap。

B 采用单因素延迟/噪声/缺失设计，具体网格和确定性随机流在配置 annexes.B 与范围决定中。现行生产观察接口不兼容此输入，B 条目不伪装成可执行正式行。

C 复用 A 的 16 对，正常为各配置参考，迟料/迟接收/带载故障为三个挑战；不重复运行同一 pair 后再当独立样本。恢复定义在分析计划固定，未恢复、未触发、截尾照录。急单、取消、质量/结构返修和物理路径故障不在当前主网格；原功能证据保留，范围扩展另列审阅，不推断已测。

CP-SAT 与 EDD/SPT/FASTEST_MODE 的现成 S16 静态开发见证只作独立参考域，正式测试行为空。若加入新静态测试集，须单独给出匹配映射、目标/保留项和求解预算；不能拿静态最优性证明全生产域最优。主四方法含固定模式和去更新消融，物理可行域保持。

## 停止、失败与补跑

固定登记规模；不按显著性、收益或领先方向提前结束。每个预定 ID 必须对应实际尝试或 NOT_RUN 理由。AUDIT_INVALID、BUDGET_EXCEEDED、WINDOW_CENSORED、TURN_LIMIT、INFRA_FAILED、MISSING_EVIDENCE、NOT_TRIGGERED 和生产终止原因并列保存；合法截尾不等于非法，但不计完成。

方法失败、无候选、预算耗尽不择优重试。基础设施失败最多同输入重试 1 次，保留两次原记录，以第一个完整且审计可用的尝试按固定规则入账；两次都失败仍失败。异常长运行停止先保存最后完整证据；部分写入不算完整结果。改协议/源码后形成新版本，标明失效及成对重跑范围；不只给较差方追加预算。

执行器必须记录 run/attempt 身份、真实配置/源/环境摘要、输入与结果文件摘要、实际开始/结束/退出、事件/决策双审计和预算。不得生成实验成功的占位结果。最终冻结前 [开发运行器](../../scripts/run_s20_development.py) 只允许 dev 行，S21 执行器未创建。
