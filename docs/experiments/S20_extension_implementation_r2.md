## 投影边界如何校验

每份实际采样先绑定真实snapshot、闭合决策前缀、配置/run/epoch、公共slot和受权settings。首次使用送达帧时，原独立执行与因果检查器重建该真实源。然后从这些**已重建的审计账**派生假想模型边界：仅对声明的F测量施加噪声并记录裁剪，模型revision/边界单独登记；历史事件中的原始人因测量不提供给搜索。

后续假想后缀继续由原独立检查逻辑从该声明边界校核，不能把执行器状态直接当审计账。该边界使用专属checkpoint，仅用于模型后缀；不使用checkpoint的普通实际执行检查拒绝这种模型历史。对外分别报告真实执行双审计和假想后缀审计的scope，不把二者混写。

帧未送达或被丢失时不提供真实当前状态；无首包则保持UNKNOWN。当前时钟只推动模型内生演进，不供应未来质量/到货/维修。真实安全盾在提案之后检查原命令，结果只用于接受/WAIT及记录，不送回搜索/评分或触发拒绝后重搜。

投影审计核对每条实际决策都有且仅有一份证明、帧来自实际事件前缀且实际送达、更新方法选择最新送达帧/无更新选择首帧、提案命令来自最近合法模型Schedule、实际命令只作时刻/revision绑定、安全拒绝有真实源依据。保存后重新构造帧、边界与候选校验，不重新搜索；数值解码保留已验证JSON的整数/浮点字节语义，混合类型Genes对采用局部显式结构检查。

## 尾部与旧证据的作用

共同窗评价源必须实际双审计有效。正长度尾部要求全部订单接收且无运行/所有者/预约，按日历生成每人REST/OFF_SHIFT区间并保留已有F/E/peak；独立检查器用闭式积分另算，不共享积分调用。

本轮另读取原S19B最终正常单件的保存末态，经原evidence-index核对配置/状态/原双审计/报告摘要后，派生272.35047973655236h至720h的15人尾部并独立核算。它是已审计保存状态上的后处理，未重新执行完整生产/Kit，也未新做该旧长事件历史的全量审计。

默认兼容由四个legacy开发通道与r1实际日志作事件/决策解压字节比较；范围仅1h开发。新扩展适用CPU；没有给新功能标Kit通过，不将旧完整链换标为当前新功能的全域证据。最终测试、调参与正式扫描继续不执行。
